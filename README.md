# Traveling Salesman Problem - Genetic Algorithm

A university team project we developed for the **Nonlinear Programming and Evolutionary Algorithms** (*Nelinearno programiranje i evolutivni algoritmi*) course at the Faculty of Technical Sciences, University of Novi Sad.

The goal was to solve the **Traveling Salesman Problem (TSP)** using a genetic algorithm: find a short route that visits every city exactly once and returns to the starting point. Since searching every possible route becomes impractical as the number of cities grows, we used an evolutionary approach to find good approximate solutions.

We didn't want to stop at printing a list of cities in the console, so we also built a small **Pygame interface**. It can draw the algorithm's route one connection at a time, or let you choose a route yourself and see how it compares with the algorithm's result.

## Features

- Solve the Traveling Salesman Problem with a **genetic algorithm** operating on permutations of cities.
- Use the included dataset of **52 cities**, or load a different `.txt` file from the `Data/` folder.
- Keep the default algorithm settings or enter custom population, generation, mutation, and other parameters.
- Run **one or multiple independent GA instances**, with multiple instances executed in parallel using Python's `multiprocessing` module; the program selects the best result.
- Use **early stopping** when the search stops improving, and **partial population resets** when progress stagnates.
- Optionally apply **2-opt local search** after the genetic algorithm to improve the resulting route further.
- View the final route as text or through a graphical interface with city icons, scenery, and distances between connected cities.
- Reveal the algorithm's graphical route **step by step** using Enter.
- Play an **interactive route-building mode** against the algorithm, with an **Undo** history of up to five moves, a route reset, a remaining-city counter, and a final distance comparison.

## How the genetic algorithm works

Each individual in the population represents a different ordering of all the cities. Its fitness is based on the **total Euclidean distance of the closed route**, including the journey from the last city back to the first. A shorter route is a better solution.

Our implementation follows these steps:

1. **Initial population:** Generate random permutations of the cities.
2. **Selection:** Rank the individuals by route length, then use a randomized, rank-weighted value to select parents. Better routes have an advantage, but selection is still stochastic.
3. **Crossover:** Take an initial segment from one parent and fill the rest with cities from the other parent in their existing order, skipping duplicates. This keeps every city in the offspring exactly once.
4. **Mutation:** Occasionally swap two cities in an offspring's route. A distance-based threshold protects sufficiently good offspring from mutation.
5. **Replacement and elitism:** Keep a configurable number of the best individuals from the previous population and fill the remaining places with offspring.
6. **Stagnation handling:** Reset part of the population after repeated lack of improvement, and stop early if stagnation continues for too long. The algorithm also stops when the configured generation limit is reached.

The genetic algorithm is stochastic, so different executions can produce different routes. It is an approximate search method, **not a guarantee of finding the globally shortest possible tour**.

### Parallel execution

We also added the option to run several copies of the genetic algorithm at the same time. Each instance searches **independently**, with its own randomly generated population. After they finish, the program compares their results and keeps the shortest route.

This isn't a single genetic algorithm with a population shared across processes; it is a practical way to try several independent searches in parallel.

### Optional 2-opt improvement

After the GA finishes, the program asks whether we want to apply **2-opt** before displaying the final route. This local-search method tries replacing pairs of connections by reversing a section of the route, keeping a change only when it reduces the total distance. It continues until it can no longer find an improvement of that kind.

The console shows the **original GA distance**, the **distance after 2-opt**, the improvement, and the city order before and after optimization. When enabled, the graphical interface uses the improved route.

In one approximate comparison, a route around **11,000** distance units became one around **8,000** after 2-opt - roughly a **27% reduction**. The improvement varies between runs and is not guaranteed to be that large; 2-opt also does not guarantee a global optimum.

## How to run

You'll need **Python 3**. Clone or download this repository, then open a terminal in its root directory.

Install the required package:

```bash
python -m pip install -r requirements.txt
```

Start the application:

```bash
python main.py
```

On Windows, `py` can be used instead of `python` if that's how Python is configured.

The menus and most on-screen messages are in **Serbian**. During execution, the program asks us to:

1. Choose the default city dataset or provide the name of another `.txt` file in `Data/`.
2. Run a single GA instance or several independent instances in parallel.
3. Use the default GA parameters or enter custom values.
4. Choose whether to apply 2-opt to the final GA result.
5. View the result in the console or open one of the two graphical modes.

### Graphical controls

| Mode | Control | Action |
| --- | --- | --- |
| Algorithm visualization | **Enter** | Reveal the next connection, eventually closing the route |
| Interactive mode | **Mouse click** | Select an unvisited city |
| Interactive mode | **Z** | Undo a previous selection (up to the last five moves) |
| Interactive mode | **R** | Clear the current route and start selecting again |
| Interactive mode | **Enter** | After visiting all cities, compare the route against the algorithm |

The interactive mode includes **Undo and Reset**, but not a separate Redo command.

### Input file format

City data is stored in `Data/`. Each row contains a city ID followed by its X and Y coordinates, separated by spaces:

```text
1 565.0 575.0
2 25.0 185.0
3 345.0 750.0
```

The program generates city names by combining words from the two name lists in the same folder. Distances are calculated from coordinates; they are **not specified in kilometers**.
